## W03 表單蒐集班級資料＋pandas 讀取

## W05 Teachable Machine 影像分類

網址：`teachablemachine.withgoogle.com` → **Get Started** → Image Project → Standard image model。每組 2～3 個類別、每類用手機相機拍 50 張、訓練後即時測試，最後把實驗數據填進表單。

| 操作 | iPhone | Android |
|---|---|---|
| 瀏覽器 | Safari 或 Chrome（先更新） | Chrome（先更新） |

<a id="w06"></a>
## W06 迴歸與分類：改參數比較

筆記本流程：第 0 格讀班級資料（沿用 W03 的 ID，留空白用示範資料）→ 線性迴歸（換 x 欄位看 R² 多低）→ KNN（k 滑桿 1～25，鳶尾花資料）→ 決策樹（depth 滑桿並印出規則）→ 延伸：用班級資料猜「手機重度使用者」。原則：**一次只改一個參數，訓練與測試兩個分數都抄在紙上**。班級資料的 R² 和分類正確率都會很低——這正是「資料有沒有關係比模型厲害不厲害重要」的教學點。

<a id="w07"></a>
## W07 Teachable Machine 調超參數

開回上週的專案（同一個 Google 帳號才找得到）→ 切電腦版網站 → Training 區塊點 **Advanced** 小箭頭 → 看到 Epochs／Batch Size／Learning Rate（預設 50／16／0.001，**先抄下預設值**）。一次只改一個值，重新訓練並記錄準確率；訓練中不要鎖螢幕、手機發燙就拔充電線調低亮度。

<a id="w08"></a>
## W08 做一個真的有用的分類器＋交叉測試

三選一題目（垃圾分類／手勢／口罩）拍照訓練 → **Export Model → Tensorflow.js → Upload my model** 產生分享連結 → 連結貼進課程表單給別組測試 → 把交叉測試結果填成混淆矩陣。別組模型在你們的場景幾乎全錯很正常——那就是「訓練資料代表性」的重點，把情況記錄下來。

## W10 中文短評情緒分析

## W11 四種 Prompt 寫法大對決（Gemini／ChatGPT）

全組挑同一個題目、同一支手機、同一個服務，**每次開新對話**依序試四種寫法，用同一把尺打分（看得懂嗎／有沒有廢話／格式對不對／內容正確嗎／能不能直接用）。

**題目卡（投影用）**

| 寫法 | 你要輸入的內容 |
|---|---|
| 一、模糊 | 介紹一下人工智慧 |
| 二、加上角色 | 你是教大一新生的助教。請用白話解釋什麼是人工智慧，讓完全沒學過程式的人也聽得懂。 |
| 三、再加輸出格式 | （承上）輸出格式：一、條列三點，每點不超過 20 個字。二、用繁體中文。三、最後補一句生活中的例子。 |
| 四、再給一個範例 | 你是教大一新生的助教。請用一句話解釋一個 AI 名詞。範例　輸入：機器學習　輸出：讓電腦從很多例子裡自己找規律。現在請依同樣格式解釋：人工智慧、深度學習、訓練資料。 |
| 追問 | 太長了，壓縮成三句話。／把專有名詞換成生活中的比喻。／最後補一句：這跟我的手機有什麼關係。 |

注意：**絕不輸入姓名、學號、電話等個資**；未達服務年齡規定就看老師投影的示範畫面，不要造假註冊；兩支手機答案不同是模型隨機性，兩份都截圖。

## W13 語音輸入 vs Whisper 轉錄

## W16 模型評估與常見陷阱

用 `w16_evaluation` 做四個實驗，讓正確率自己現出原形。**全程不吃網路、不用相機**，只要改標了「← 改這裡」的那一行，是全學期網路壓力最小的一堂。

| 任務 | 學生要做的事 | 會看到什麼 |
|---|---|---|
| 一 | 第 1 格改 `bad`（1 → 5 → 20），每次記兩個數字 | 正確率和「全猜好品基準」越接近，模型越沒有做事 |
| 二 | 第 2 格直接按 ▶，印出混淆矩陣四格 | 四格加起來要等於 500，先做這個檢查再看指標 |
| 三 | 第 3 格改 `th`（0.3／0.5／0.7／0.9 各跑一次） | 門檻調高，精確率往上、召回率往下 |
| 四 | 第 4 格直接按 ▶，比較有洩漏與沒洩漏 | 上面那個分數比較高，但它一點意義都沒有 |

**門檻紀錄表（投影出來，當堂收）**：四列都填滿才看得見此消彼長，最後一列要寫理由。

| 判斷門檻 | 精確率 | 召回率 | 你看到什麼 |
|---|---|---|---|
| 0.3 | 　 | 　 | 門檻低：抓得多，誤報也跟著多 |

<a id="w17"></a>
## W17 邊緣 AI 與智慧物聯網

**這一週的主體在手機上，不在筆記本裡**：把第 8 週的 Teachable Machine 模型在飛航模式下跑起來並計時，`w17_edge_ai` 只負責**記錄與分析**。全程不連任何 API、不需要金鑰。

| 任務 | 在哪裡做 | 要交什麼 |
|---|---|---|
| 一 | 手機：開回第 8 週模型連結 → 允許相機 → 等到出現即時百分比 → 開飛航模式（Wi-Fi 也要關）→ 另開分頁確認連不上 → 回頭繼續辨識 | 同時拍到飛機圖示與辨識結果的截圖 |
| 二 | 老師計時頁量十次（`N = 10`，計時只包住 `predict` 那一行）→ 十個數字貼進筆記本第 1 格 | 延遲紀錄表（平均、中位數、最快最慢） |
| 三 | 手機維持飛航模式，測四個 App 的離線可用性 | 分成「裝置上算」與「一定要連網」兩類 |
| 四 | 筆記本第 3 格：六個應用的邊緣／雲端判斷表 | 六題各一句理由，缺理由不計分 |

**筆記本三格在做什麼**：第 1 格把十次延遲算出平均、中位數、最快最慢與「一秒能跑幾次」；第 2 格用 `photo_kb × 8 ÷ up_mbps ＋ rtt ＋ server` 估雲端來回是本地的幾倍（**1 Mbps 就是每毫秒 1 kb**）；第 3 格把六個應用的判斷輸出成表格並檢查有沒有漏填。

**課前準備與調度**：提前一週提醒學生找回第 8 週的模型分享連結、把手機充飽電並清出容量。全班同時載模型會塞車，**請分兩批**：單號組先載，雙號組先做任務三的表。模型一旦載完，後面全部不吃網路。

**上課要講的兩個點**：第一次量到的延遲最慢是正常的（模型暖機與記憶體配置）；連續量十次手機會發熱降頻，所以**中位數比平均可靠**。判斷口訣：快、省、密、斷。

延伸挑戰：A 把第 2 格的 `up_mbps` 從 4 改成 1，看雲端來回變成幾倍；B 換暗一點的環境或換一支手機再量十次；C 說出為什麼量化能同時讓檔案變小又讓推論變快，代價是什麼。
