# 主題 8 6LoWPAN 與 IPv6：上機程式（Pico 2 W ×2，不需要 Linux、不裝 Wireshark）

Pico 2 W 沒有 802.15.4 無線電，MicroPython 也沒有 IPv6 堆疊（所以不會回 ping6）。這次的做法是：
**A 板（感測節點）用程式組出「位元組完全合乎標準」的 802.15.4＋6LoWPAN＋IPv6＋UDP 訊框**，
用 Wi-Fi UDP 當「假的實體層」送給 **B 板（收集端）**；B 驗 FCS、重組、解壓縮，印出欄位樹；
最後把 B 印的十六進位貼到電腦上的 `wsn_decode.py`，用另一份程式再解一次（第二方驗證）。

## 先做這三件事
1. 兩片板子都存一份 `myid.py`（全課共用），只改前三行：`STUDENT_ID`（組長學號）、`GROUP`（組號）、`BOARD`（這片是 A 還是 B）。
2. 下面這些檔案原封不動存到**兩片板子**：`cfg.py`、`ap_a.py`、`sta_b.py`、`wsnproto.py`、`wsntree.py`（協定函式庫，老師給的，不要改）。
   匯入時出現 `MemoryError`：改存 `mpy/wsnproto.mpy`、`mpy/wsntree.mpy`，並把板子上同名的 `.py` 刪掉。
3. 電腦上把 `wsn_decode.py`、`wsnproto.py`、`wsntree.py` 放在同一個資料夾（只有 `wsn_decode.py` 也能跑，它裡面有內建一份）。

每支程式第一行都是 `import myid`，截圖要看得到 myid 印出的那一行（學號｜第幾組｜板子 A／B｜序號｜MAC｜日期時間）和右下角的時間。
Thonny 第二次執行沒印出這一行時，先按 Stop（軟重開）再執行。

## 執行順序（每個任務都一樣）
1. **B 先跑**（任務一～五跑 `rx_b.py`，任務六跑 `loss_b.py`）：B 會連上 A 的 AP，每秒「報到」一次，直到 A 回應。
2. **A 再跑**這個任務的程式：A 開 AP、等 B 報到（順便交換兩片的 MAC），再把訊框送出去。
3. B 印出：指紋、十六進位、欄位樹。**把「指紋」那一行和底下的十六進位（0000、0010… 開頭的幾行）一起複製**。
4. 電腦端：Thonny 右下角把直譯器切到「本機 Python 3」→ 打開 `wsn_decode.py` 按執行 → 在 Shell 貼上 → 再按一次 Enter。
   對照 B 印的欄位樹和電腦印的欄位樹，兩邊要一樣。做完再切回 MicroPython 做下一個任務。
   （也可以每個任務先把複製的文字存進記事本，最後一次切過去全部貼上。）

## 誰跑哪支程式
| 任務 | A 板（感測節點，送） | B 板（收集端，收） | 配分 |
|---|---|---|---|
| 一 位元組預算與位址推導 | `t1_addr_a.py` | `rx_b.py` | 15% |
| 二 不壓縮的 IPv6（0x41，68 位元組） | `t2_raw_a.py` | `rx_b.py` | 15% |
| 三 IPHC＋NHC：一次轉一顆旋鈕（25 位元組）＋手寫 parse_iphc | `t3_iphc_a.py`（改 `KNOB` 0～4） | `rx_b.py`；`iphc.py` | 25% |
| 四 FCS（CRC-16）與錯一個位元 | `t4_fcs_a.py` | `rx_b.py`（先把 `FCS = None` 改成 `True`） | 15% |
| 五 分片與亂序重組（198 位元組切 2 片） | `t5_frag_a.py` | `rx_b.py` | 20% |
| 六 遺失放大 1−(1−p)^n | `t6_loss_a.py` | `loss_b.py` | 10% |

### 任務一
- A 先印出 127 位元組的預算：短位址＋PAN 壓縮的 MAC 標頭 9、兩個長位址 21，各剩多少能放 IPv6 和資料。
- A 用自己的 Wi-Fi MAC 推出 EUI-64 → IID（第一個位元組翻轉 U/L 位元，28 變 2a）→ link-local；也替 B 算一次。
- A 用兩個 64 位元長位址送一包（37 位元組）。B 的欄位樹裡，IPv6 來源位址要等於 A 算的、目的位址要等於 B 自己開頭印的。

### 任務二
- A 送不壓縮的版本：分派值 `41`＋完整 40 位元組 IPv6 標頭＋8 位元組 UDP＋10 位元組資料，共 68 位元組。
- 和投影片的答案卷逐位元組對照（這一包和答案卷一模一樣）。

### 任務三
- 同一包改用 IPHC＋NHC：25 位元組（`7e 33 f3 12 d9 52`…）。再把 `KNOB` 依序改成 1、2、3、4，每次重跑 A（B 也要重跑），
  把 A 印的「壓縮後標頭」填進記錄表：
  1 → UDP 不壓（`7a 33 11 …`，11 位元組）、2 → 跳數上限 30（多帶 1 位元組）、3 → 來源埠 5683（多帶 2 位元組）、
  4 → 全域位址＋context 0（`7e 77 …`）。旋鈕 4 在電腦端要先打 `ctx 0 2001:db8:1::/64` 再貼，不然會說 context 0 沒設定。
- 在 B 板執行 `iphc.py`：手寫的 `parse_iphc` 解 `7A 33` 和 `7E 33`，對照 B 的欄位樹。

### 任務四
- B 的 `rx_b.py` 先把 `FCS = None` 改成 `FCS = True`（真的 802.15.4 接收端一定知道訊框尾巴有 FCS）。
- A 先印 CRC-16 自我檢查 `0x2189`，再送一個好的訊框（27 位元組，尾巴 `dd bf`）和一個「只翻了 1 個位元」的訊框（25.3 變 25.2）。
- B：好的全部正確；壞的那個停在 MAC 層，說明「FCS 錯誤：接收端應該整個訊框丟掉」。

### 任務五
- 150 位元組資料 → IPv6 封包 198 位元組 → 切成 FRAG1（123 位元組）＋FRAGN（60 位元組）。
- A 故意先送 FRAGN、再送一次 FRAGN（重複）、最後才送 FRAG1。看 B 的三行「說明：重組…」：開新緩衝 → 重複的不理 → 拼完 198。
- 試試看把 `ORDER` 改成 `(1,)`（只送 FRAGN）：5 秒後 B 印出「重組逾時」。

### 任務六
- B 先跑 `loss_b.py`（預設每一片 10% 機率假裝掉了；接了可變電阻就把 `USE_KNOB` 改成 True），A 再跑 `t6_loss_a.py`。
- A 每種片數 n＝1～6 各送 100 包（約 1 分鐘）。B 印出「拼回幾包、成功率、理論 (1−p)^n」，填進記錄表。

## 接線（B 板，選做）
- GP15（第 20 腳）→ 220Ω → LED 長腳，短腳 → GND（第 18 腳）：這個訊框全部正確就亮。
- GP16（第 21 腳）→ 220Ω → 第二顆 LED，短腳 → GND（第 23 腳）：每收到一個訊框換一次亮暗。
- 任務六的遺失旋鈕：10 kΩ 可變電阻兩端接 3V3(OUT)（第 36 腳）與 AGND（第 33 腳），中間腳接 GP26（第 31 腳）。

## 分組參數（cfg.py 自動算）
- SSID：`wsn-gNN`（NN＝兩位數組號）；密碼：`pico` 加上「組號 × 1234 取後四位」；AP 頻道 1、6、11 輪流（和主題 3 一樣）。
- UDP 埠：A 收報到 5080；B 收訊框 5000＋組號（分組參數表的 UDP 埠）。
- PAN ID 用答案卷的 `0xABCD`，短位址 A＝`0x0002`、B＝`0x0001`，所以你們的位元組可以和投影片逐一對照。

## 延伸挑戰（不計分）
- A 反向壓縮：自己寫 `build_iphc()`，用左移和 `|` 把欄位拼回 `7A 33`，丟回 `parse_iphc` 檢查。
- B NHC 解碼：在 `parse_iphc` 後面接著解 NHC-UDP 的 `11110CPP` 和兩個埠號（旋鈕 3 的 `f1 16 33 b2` 是好練習）。
- C 位址推導：把 `cfg.PAN` 改成分組參數表的 `0x10NN`，看任務三的訊框哪幾個位元組變了；`TAG` 改成學號後四位，看 FRAG1／FRAGN 哪兩個位元組變了。
- D 感測整合：任務三的資料改成 AHT20 真的溫溼度（SDA→GP4 第 6 腳、SCL→GP5 第 7 腳）。
